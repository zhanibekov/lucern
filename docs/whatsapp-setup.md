# Подключение WhatsApp-бота

Код подготовлен для сайта «Дастан-4». Для запуска нужны ваш сайт в Netlify,
приложение Meta с WhatsApp Cloud API и ключ OpenAI API. Само приложение
WhatsApp Business на телефоне не предоставляет API-ключи.

## Как это работает

`Meta → whatsapp → whatsapp-reply-background → OpenAI → WhatsApp Cloud API`

- `netlify/functions/whatsapp.ts` подтверждает webhook, проверяет подпись исходного
  тела запроса с помощью `META_APP_SECRET` и ставит задачу в фон.
- `netlify/functions/whatsapp-reply-background.ts` повторно проверяет подпись,
  получает ответ ИИ и отправляет его только автору входящего сообщения.
- `server/whatsapp/reply.ts` задает правила бота и берет факты из `src/data/products.ts`.
  Цены «по запросу» не превращаются в нулевую стоимость. Наличие и сроки уточняются у менеджера.
- Netlify Blobs хранит отметки отправки, чтобы повторные webhook не создавали
  повторные ответы. Отдельные ключи для Blobs в Netlify Functions не нужны.

## 1. Подготовить Meta и OpenAI

Начните с тестового номера Meta и своего номера-получателя в API Setup.
Не удаляйте и не переносите существующий рабочий номер ради теста.
Подключение текущего номера WhatsApp Business нужно отдельно проверить в доступном
вашему аккаунту процессе Meta; наличие приложения на телефоне не означает, что Cloud API подключен.

В Meta потребуются:

- App Secret приложения;
- WhatsApp access token с правом `whatsapp_business_messaging`;
- Phone Number ID тестового номера (это ID, а не сам номер телефона);
- поддерживаемая версия Graph API из примера запроса в API Setup.

Временный токен Meta подходит для теста. Для постоянной работы потребуется
подходящий токен системного пользователя и назначенные ему ресурсы WhatsApp.
OpenAI API оплачивается отдельно от подписки ChatGPT.

## 2. Переменные Netlify

Добавьте переменные в настройки проекта Netlify. Секретам нужен scope **Functions**
и context **Production**; не выдавайте рабочие секреты Deploy Previews.
Если ваш интерфейс не позволяет выбирать scope, используйте все scopes без префикса `VITE_`.

| Переменная | Значение |
| --- | --- |
| `WHATSAPP_VERIFY_TOKEN` | Придуманная вами длинная случайная строка для проверки webhook |
| `META_APP_SECRET` | App Secret из настроек приложения Meta |
| `WHATSAPP_TOKEN` | Access token WhatsApp Cloud API |
| `WHATSAPP_PHONE_NUMBER_ID` | Phone Number ID из Meta |
| `WHATSAPP_API_VERSION` | Версия из Meta, в формате `vNN.0`; буквальный `vNN.0` не подходит |
| `OPENAI_API_KEY` | Ключ проекта OpenAI API |
| `OPENAI_MODEL` | `gpt-4.1-mini` — модель по умолчанию; можно заменить доступной Responses-моделью |
| `WHATSAPP_BOT_ENABLED` | Сначала `false` |
| `WHATSAPP_ALLOWED_NUMBERS` | Ваш тестовый номер: код страны и цифры, без `+`, пробелов и скобок |

Несколько тестовых номеров разделяются запятыми. **Пустой список разрешает ответы всем**,
если `WHATSAPP_BOT_ENABLED=true`. Изменив переменные, выполните новый deploy.
Не вставляйте ключи в чат, исходники сайта или Git. `.env` исключен из Git;
`.env.example` содержит только пустые поля и открытые настройки.

Для проверки webhook достаточно `WHATSAPP_VERIFY_TOKEN` и `META_APP_SECRET`:
остальные поля понадобятся при включении ответов. `GEMINI_API_KEY` для этого бота не нужен.

## 3. Опубликовать код

Netlify должен собирать **этот репозиторий**, командой `npm run build`, с публикацией `dist`.
Папка функций задана в `netlify.toml`: `netlify/functions`. Используйте Node.js 22.
После согласованного push в подключенную ветку дождитесь успешного deploy.
Перетаскивание одной папки `dist` не публикует серверные функции.

Проверьте, что в Netlify появились обе функции: `whatsapp` и
`whatsapp-reply-background`. Нужны доступные вашему тарифу Background Functions
и Netlify Blobs. Код не требует отдельного VPS.

## 4. Подключить webhook

В настройках WhatsApp приложения Meta укажите:

- Callback URL: `https://ВАШ-САЙТ.netlify.app/.netlify/functions/whatsapp`
- Verify token: точно такое же значение, как `WHATSAPP_VERIFY_TOKEN` в Netlify.

Дождитесь подтверждения и подпишитесь на поле **messages**.
Приложение также должно быть подписано на нужный WhatsApp Business Account.
В Meta используйте именно `whatsapp`, а не фоновую функцию.

Функция возвращает challenge обычным текстом. Неверный token или подпись → 403.
Незаполненная конфигурация → 503. Подтверждение webhook еще не означает, что бот отвечает.

## 5. Проверить ответ со своего телефона

1. Заполните все переменные, укажите свой номер в `WHATSAPP_ALLOWED_NUMBERS`.
2. Поставьте `WHATSAPP_BOT_ENABLED=true` и выполните deploy.
3. Со своего разрешенного номера отправьте тестовому номеру Meta:
   «Здравствуйте! Какие есть фасовки семян люцерны?».
4. Проверьте ответ на русском, затем напишите вопрос на казахском.
5. Убедитесь, что бот не придумывает стоимость и не отвечает повторно на одно сообщение.
6. Проверьте логи обеих функций в Netlify, затем настройте рабочий номер Meta.
7. После проверки можно очистить список разрешенных номеров и выполнить deploy.

Выключение: `WHATSAPP_BOT_ENABLED=false`, затем deploy. Подтверждение webhook продолжит работать.

## Ограничения первой версии и сбои

- Обрабатываются текстовые сообщения с телефонным идентификатором отправителя.
  Фото, голосовые, документы, интерактивные ответы и события статусов игнорируются.
  Поддержка новых идентификаторов пользователей без номера телефона не реализована.
- Каждый ответ использует текущее сообщение и каталог. Памяти переписки нет;
  это консультант по отдельным вопросам, не полноценная система оформления заказов.
- Бот не создает заказ, не принимает оплату и не передает сообщения менеджеру.
  Формы сайта по-прежнему сохраняют заявки в браузере посетителя.
- Бот берет опубликованный каталог, а не изменения характеристик в localStorage.
- Сообщения старше 23 часов пропускаются, чтобы оставить запас внутри окна
  обслуживания WhatsApp. Шаблонные рассылки и исходящие сообщения по инициативе бизнеса не реализованы.
- Webhook подтверждается только после HTTP 202 от фоновой функции.
  При ошибке постановки возвращается 503. Фоновая функция бросает ошибку для повторных
  попыток Netlify. Их число ограничено; после исчерпания нужен разбор логов.
- При повторной доставке одного сообщения одновременно возможны два запроса к ИИ,
  но атомарная запись в Blobs разрешает только одну попытку отправки.
- При таймауте отправки неизвестно, приняла ли Meta сообщение. Бот сохраняет отметку
  `uncertain` и автоматически не пересылает его, чтобы избежать дублей. Сбой сразу
  после записи `sending` тоже требует ручной проверки. Это не гарантия доставки ровно один раз.
- `sent` означает, что API Meta принял сообщение, а не что клиент его прочитал.
  Статусы фактической доставки в этой версии не отслеживаются.
- В Blobs остаются SHA-256 ключи сообщений, состояние и время; текстов и телефонов
  там нет. Автоматическая очистка отметок не реализована. Для очистки используйте
  раздел Blobs Netlify и удаляйте только записи старше 24 часов.
- Текст входящего сообщения передается OpenAI. `store:false` отключает сохранение
  Response для последующего получения через API, но не является обещанием нулевого
  хранения данных провайдером. Приложение не пишет тексты, телефоны и токены в логи.
- Стоимость и лимиты API/Netlify зависят от аккаунтов. Ограничения длины запроса
  и ответа есть, отдельного суточного ограничения числа сообщений нет.

## Проверки разработчика

```sh
npm ci
npm test
npm run lint
npm run build
```

Тесты используют подставные HTTP-ответы и хранилище: они не отправляют реальные сообщения
и не расходуют API. Окончательная проверка Netlify/Meta выполняется после настройки аккаунтов.
`npm run dev` запускает только Vite. Для локальной работы функций можно использовать
Netlify Dev; `.env.local` заполните вручную, а рабочие ключи не помещайте в preview.
